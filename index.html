Verification pipeline

Every analysis runs through three stages in real-time

1

Claim extraction

The input text is parsed into individual, atomic factual statements. Each sentence is analyzed and broken into its constituent claims — separating opinions, subjective statements, and connective tissue from verifiable facts.

NLP Parsing Sentence Segmentation Fact vs Opinion Detection
2

Source retrieval

Each extracted claim is searched against a curated set of trusted knowledge bases — including Wikipedia, official documentation, government databases, academic publications, and authoritative reference sites. Multiple sources are retrieved per claim.

Knowledge Graph Lookup Semantic Search Multi-source Retrieval
3

Verification & scoring

Claims are cross-referenced against retrieved sources using entailment analysis. A confidence score (0–100%) is computed based on source agreement, source authority, and specificity of the match. Each claim is classified as verified, unverifiable, or incorrect.

Entailment Analysis Confidence Scoring Source Weighting

Claim classifications

Verified

The claim is directly supported by at least one trusted source with high confidence. The source, link, and matching evidence are provided.

Unverifiable

No matching source could confirm or deny the claim. This doesn't mean it's false — just that it cannot be independently verified with available data.

Incorrect

The claim is contradicted by trusted sources. The correct information and the contradicting source are provided for transparency.

About

HF3-SW-22 · Hallucination Hunter

What is this?

A claim-level fact-verification layer for LLM outputs that visually distinguishes verified, unverifiable, and false claims with source attribution — improving user trust and transparency in AI-generated answers.

How it works

  1. Claim extraction — Parses any LLM response into individual, atomic factual claims.
  2. Source retrieval — Searches trusted knowledge bases for each claim.
  3. Verification & scoring — Cross-references each claim against retrieved sources and assigns a confidence score.
  4. Visual annotation — Highlights the original text with color-coded claim statuses and detailed source attribution.

Tech stack

  • Frontend — Vanilla HTML/CSS/JS with DM Sans typography
  • Database — Supabase (PostgreSQL) for real-time persistence
  • Verification — Pattern-matched claim database (demo) / LLM API (production)
