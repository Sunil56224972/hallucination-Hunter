1. How LLaMA AI Model Works

1.1 What is LLaMA?

LLaMA stands for "Large Language Model Meta AI". It is an open-source AI model created by Meta (Facebook). LLaMA 3 is the version we use in Hallucination Hunter.

💡 Simple Explanation

Think of LLaMA like a super-intelligent text reader. You give it text, and it understands it like a human — it can break sentences into facts, check if they sound true, and explain why something might be wrong.

1.2 LLaMA Architecture (Transformer Model)

LLaMA is based on the Transformer architecture, which is the foundation of all modern AI language models. Here's how it works step by step:

Step 1: Tokenization (Breaking Text into Pieces)

When you type "The Earth orbits the Sun", LLaMA doesn't read it like a human. It breaks the text into small pieces called tokens:

"The Earth orbits the Sun"
  → ["The", " Earth", " orbits", " the", " Sun"]
  → [464, 7948, 103937, 279, 8219]  (number IDs)

Each token is converted to a number. The model only understands numbers, not words.

Step 2: Embeddings (Numbers → Meaning)

Each token number is converted into a vector — a list of 4,096 numbers that capture the meaning of that word. Words with similar meanings have similar vectors.

"King"  → [0.82, -0.41, 0.33, 0.91, ...]  (4,096 numbers)
"Queen" → [0.79, -0.38, 0.35, 0.88, ...]  (similar!)

Step 3: Self-Attention (Understanding Relationships)

This is the magic of LLaMA. Self-attention allows each word to look at every other word and understand how they relate:

  • In "The bank of the river" — the word "bank" looks at "river" and understands it means "river bank" (not a financial bank).
  • LLaMA 3 has 32 attention heads — it looks at relationships from 32 different perspectives simultaneously.

Step 4: Feed-Forward Network (Deep Thinking)

After attention, the data passes through dense neural network layers that process the combined information. This is where the model "thinks" about what the text means.

Step 5: Layer Stacking (80 Layers Deep)

Steps 3 and 4 repeat 80 times in LLaMA 3 (80 transformer layers). Each layer adds deeper understanding:

  • Layer 1-10: Basic grammar and word patterns
  • Layer 11-40: Sentence meaning and context
  • Layer 41-60: Facts, knowledge, and reasoning
  • Layer 61-80: Complex logic and final output

Step 6: Output Generation

The final layer produces a probability for every possible next token. The model picks the most likely token, adds it to the text, and repeats until done.

Input Text → Tokenizer → Embeddings → Self-Attention ×80 → Output

1.4 Why We Use Groq for LLaMA

LLaMA is just the model — it needs hardware to run. Groq is a company that has special AI chips called LPU (Language Processing Units) that run LLaMA extremely fast.

⚡ Speed Comparison

NVIDIA GPU: ~30-50 tokens/second

Groq LPU: ~500-800 tokens/second (10-15x faster!)

This is why our app gives results in under 2 seconds.

2. How APK Was Built from a Web App

2.1 The Problem

❌ Problem

We built Hallucination Hunter as a web app (HTML + CSS + JavaScript). But users want to install it on their Android phones like a real app from the home screen — not just visit a website.

2.2 The Solution: Capacitor

✅ Solution

We used Capacitor (by Ionic) to wrap our web app inside a native Android container. The web app runs inside an Android WebView — it's like a browser without the address bar, running as a standalone app.

2.3 What is Capacitor?

Capacitor is a tool that takes your web app (HTML/CSS/JS) and wraps it inside a native Android or iOS app. The key benefits:

  • Same code — No need to rewrite in Java/Kotlin
  • Native features — Access to camera, GPS, notifications
  • App store ready — Generates proper APK file
  • WebView — Uses Android's built-in browser engine

2.4 Step-by-Step APK Build Process

Step 1: Initialize Capacitor Project

npm init -y
npm install @capacitor/core @capacitor/cli
npx cap init "Hallucination Hunter" "com.sunildev.hallucinationhunter"

This creates a capacitor.config.ts file that tells Capacitor where to find our web files.

Step 2: Add Android Platform

npm install @capacitor/android
npx cap add android

This creates an android/ folder with a full Android Studio project — including MainActivity.java, AndroidManifest.xml, and Gradle build files.

Step 3: Copy Web Assets

npx cap copy android

This copies all web files (HTML, CSS, JS, images, icons) into:

android/app/src/main/assets/public/
  ├── index.html
  ├── app.js
  ├── style.css
  ├── config.js
  ├── verified-icon.png
  ├── unverifiable-icon.png
  └── incorrect-icon.png

Step 4: Configure Android App

We customize these files for branding:

FilePurpose
AndroidManifest.xmlApp name, permissions, orientation
styles.xmlSplash screen, status bar color
colors.xmlTheme colors (warm brown palette)
mipmap-*/ic_launcher.pngApp icon in 5 sizes (48-192px)

Step 5: Build the APK

cd android
./gradlew assembleDebug

Gradle compiles everything into a single .apk file that can be installed on any Android phone.

Web App (HTML/CSS/JS) → Capacitor → Android WebView → APK File

2.5 How the App Runs on Phone

1. User taps the app icon on their home screen

2. Android opens MainActivity.java

3. MainActivity creates a WebView (embedded browser)

4. WebView loads index.html from assets/public/

5. The web app runs exactly like it does in Chrome

6. User sees a full native-looking app with bottom navigation

3.2 Step-by-Step Technical Breakdown

Step 1: User Input (Frontend)

The user types or pastes AI-generated text into the textarea and clicks "Analyze".

// app.js — When user clicks Analyze
const userText = document.getElementById('main-input').value;
// Text is stored in a JavaScript variable in the browser

Step 2: Frontend → Vercel API (HTTPS POST)

The browser sends the text to our serverless API using a fetch() request:

// app.js — Sending data to server
const response = await fetch('/api/groq', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    text: userText,
    action: 'analyze'    // tells API what to do
  })
});

🔒 Security Note

The API key for Groq is stored on the server (Vercel environment variable), never exposed to the user's browser. This prevents API key theft.

Step 3: Vercel Serverless Function (Backend)

Our api/groq.js file receives the request on Vercel's servers and forwards it to Groq:

// api/groq.js — Server-side code
export default async function handler(req, res) {
  const { text, action } = req.body;
  
  // Build the prompt for LLaMA
  const prompt = `Extract all factual claims from this text. 
  For each claim, determine if it is verified, unverifiable, 
  or incorrect. Return as JSON array.
  
  Text: "${text}"`;
  
  // Send to Groq API
  const groqResponse = await fetch(
    'https://api.groq.com/openai/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.GROQ_API_KEY}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      model: 'llama3-70b-8192',
      messages: [{ role: 'user', content: prompt }],
      temperature: 0.1  // Low = more factual, less creative
    })
  });
}

Step 4: Groq Cloud Processes with LLaMA 3

Inside Groq's data center, this happens:

  1. Tokenize: The prompt is broken into tokens
  2. Process: LLaMA 3 (70B) runs through all 80 transformer layers
  3. Extract Claims: The model identifies each factual statement
  4. Verify Each Claim: Based on its training data (15 trillion tokens of internet text), it determines if each claim is true, false, or unverifiable
  5. Generate JSON: The model outputs structured JSON with claims, verdicts, and confidence scores

Step 5: Groq → Vercel (JSON Response)

Groq returns a structured JSON response:

{
  "claims": [
    {
      "claim": "The Earth orbits the Sun",
      "status": "verified",
      "confidence": 98,
      "source": "NASA",
      "category": "Science",
      "explanation": "Confirmed by centuries of astronomical observation"
    },
    {
      "claim": "Python was created in 2005",
      "status": "false",
      "confidence": 96,
      "correction": "Python was created in 1991 by Guido van Rossum",
      "source": "Wikipedia"
    }
  ],
  "trust_score": 67
}

Step 6: Vercel → Browser (HTTPS Response)

Our serverless function parses the response and sends clean JSON back to the browser:

// api/groq.js — Send results back
const data = await groqResponse.json();
const claims = JSON.parse(data.choices[0].message.content);
res.status(200).json({ claims, trust_score: calculateTrust(claims) });

Step 7: Browser Displays Results (Frontend)

The JavaScript receives the JSON and builds the visual UI:

// app.js — Display results
const data = await response.json();

// Draw trust score donut chart
drawDonutChart(data.trust_score);

// Build claim cards with color-coded badges
data.claims.forEach(claim => {
  const card = createClaimCard(claim);
  // Green badge = verified, Red = incorrect, Yellow = unverifiable
  claimsGrid.appendChild(card);
});

4. Problem & Solution

4.1 The Core Problem

❌ AI Hallucination Problem

What: Large Language Models (ChatGPT, Gemini, Claude) generate text that sounds confident and accurate, but sometimes contain completely fabricated "facts" — called hallucinations.

Why it's dangerous: Students, professionals, and journalists use AI-generated text without fact-checking, spreading misinformation unknowingly.

Scale: Studies show LLMs hallucinate in 5-15% of their factual claims. With billions of daily AI queries, this means millions of false facts spread every day.

4.2 Existing Problems (Before Our Solution)

❌ Problem 1: Manual fact-checking is too slow

A single article with 20 claims would take 30-60 minutes to verify by hand using Google searches.

❌ Problem 2: No automated claim-level verification

Tools like GPTZero only detect IF text is AI-generated, not WHICH specific facts are wrong.

❌ Problem 3: Users can't tell which parts are true

A paragraph might have 8 true facts and 2 false ones — but it all reads the same. There's no way to visually see which claims are trusted.

❌ Problem 4: No confidence scoring

Even when you fact-check, you don't know HOW confident the verification is. Is it 60% sure or 99% sure?

4.3 Our Solution: Hallucination Hunter

✅ Solution 1: Automated claim extraction

LLaMA 3 automatically extracts every factual claim from the text in under 2 seconds — no manual work needed.

✅ Solution 2: Claim-level verification

Each individual claim gets its own verdict: Verified ✅, Unverifiable ⚠️, or Incorrect ❌. Not just "AI-generated" — but specifically which facts are wrong.

✅ Solution 3: Visual color-coded results

Green starburst badge = verified, Yellow = unverifiable, Red = incorrect. Users can instantly see which claims to trust at a glance.

✅ Solution 4: Confidence scoring with source attribution

Every claim gets a confidence percentage (0-100%) and links to the trusted source that was used to verify it (Wikipedia, NASA, WHO, etc.).

✅ Solution 5: Overall Trust Score

An animated donut chart shows the overall trustworthiness of the entire text — making it instantly clear whether the AI output is reliable.
